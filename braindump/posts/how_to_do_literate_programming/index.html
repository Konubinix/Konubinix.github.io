How to Do Literate Programming

Braindump

Prose is the primary artifact

A literate program is first and foremost a piece of writing. You can read it from start to finish, skipping all code blocks, and still fully understand the problem, the solution, and the reasoning behind it. Code blocks are inline translations of specific sentences in the prose — they are inserted in the middle of the text without breaking its flow.

Prose is richer than code: the why is never translated.

Prose states the what, the how, and the why

Every code block is motivated by what precedes it in the prose:

  • The what (the desired behavior) → translated into a test
  • The how (the chosen technical approach) → translated into code
  • The why (the reason for the choice) → stays in prose, untranslated

No block should exist unless the prose has made it necessary. If you find yourself adding a block without the prose having led to it, a piece of reasoning is missing.

Natural order: test before code

When the prose asserts a behavior, the test comes first — it is the translation of the what. The code follows — it is the translation of the how. This order reflects the fact that we know what we want before we know how to achieve it.

Prose: "a duplicate in the list would make the tally incoherent,
        so we block creation and display an error message"

  [test — translates "we block and display a message"]
  [code — translates "we validate the list and expose a createError getter"]

Prose: "these getters go through defineProperty because Object.assign
        does not copy accessors"

  [code — translates this technical constraint]

Translation asides

Sometimes the translation is not obvious: the intent is clear but its shape in code is surprising. In that case a short paragraph can act as a translator’s note: “we want X, but in code this is written as Y because Z”.

This is not code description — it is an explanation of the gap between intent and form. These asides should be rare and clearly identifiable as such (e.g. introduced by “In practice,” or “Under the hood,”).

Prose must be readable without the blocks

Sanity check: mentally remove all code blocks. The remaining text must form a coherent and complete narrative. If a gap appears, either a paragraph is missing, or an existing paragraph was only describing a block rather than advancing the reasoning — and needs to be rewritten accordingly.

What to avoid

  • A paragraph whose only purpose is to describe the block that follows (“this function does X, it takes Y as a parameter…”). Prose states the need, not a paraphrase of the code.
  • A block with no motivation in the preceding prose.
  • A standalone “test paragraph” separated from the main narrative: if a behavior is worth testing, it is worth stating in the narrative, and the test follows naturally.
