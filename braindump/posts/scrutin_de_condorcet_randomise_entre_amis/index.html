Pitch et contraintes

Voter à la majorité paraît simple, mais dès qu’il y a plus de deux options la majorité se perd dans les paradoxes. Le scrutin de Condorcet répare ça en regardant chaque duel entre candidats. Quand il n’y a pas de vainqueur net (un cycle), on départage par un tirage au sort dans le Smith set — reproductible, parce que la graine est le hash des bulletins clos, pas un appel serveur.

Cette app est un outil de vote entre amis. Ce n’est pas un système officiel : on peut bidouiller le bulletin du copain en inspectant IndexedDB. Ça suffit pour un apéro ou un choix de film en famille, et ça tient dans un seul fichier HTML.

Les deux modes d’utilisation

L’app supporte deux modes de vote, au choix à la création du scrutin :

  1. Appareil partagé : tout le monde vote sur le même téléphone à tour de rôle. Entre deux votants un écran-tampon masque l’UI et invite à passer le téléphone. Le votant suivant ne voit jamais le classement du précédent.
  2. Un appareil par personne : chacun ouvre le lien du scrutin sur son téléphone et vote séparément. La sync est assurée par le serveur automergesync via WebSocket Automerge. Le flux UX de ce mode (identification du votant, pas d’écran-tampon) n’est pas encore câblé — le toggle est désactivé dans le formulaire de création.

Le mode se choisit à la création et conditionne le flux de vote.

Secret du bulletin

Règle dure : pendant qu’un votant classe ses candidats, il ne voit aucun bulletin déjà soumis. Deux conséquences concrètes :

  • En mode appareil partagé, la liste des candidats à classer est réinitialisée et mélangée pour chaque votant, pour qu’on ne puisse pas reconstruire l’ordre soumis par le précédent à partir de la position initiale.
  • L’écran de vote n’affiche jamais la matrice des duels, les totaux partiels, ni la liste des bulletins. Ces vues n’apparaissent qu’après la clôture du scrutin.

Le compteur “n votants / m inscrits” et la liste des voters ayant déjà voté sont considérés comme non-secrets : ils n’indiquent pas comment ils ont voté. C’est l’opacité sociale minimale acceptable pour un vote entre amis.

Bibliothèques externes

On ne réinvente aucune roue. Les seules briques tierces, toutes chargées via esm.sh dans l’import map :

  • petite-vue — réactivité de l’UI, directives HTML v-show, v-for, v-model, @click. Pas de build step, ~6 KB.

  • Automerge 2 + automerge-repo 1 + automerge-repo-storage-indexeddb

    • automerge-repo-network-websocket — CRDT local-first,

    persistance IndexedDB, sync WebSocket vers le serveur automergesync. Un scrutin = un doc Automerge, identifié par son URL automerge:<hash>, partageable comme lien d’invitation.

  • SortableJS — drag-and-drop pour réordonner les candidats. Framework-agnostic, intégration petite-vue triviale.

  • API Web Crypto native — hash SHA-256 pour la graine de tie-break.

Le WASM d’Automerge n’étant pas chargeable directement depuis le shim par défaut d’esm.sh (la dépendance circulaire du fichier slim.mjs rend les exports vides), on contourne avec deux astuces documentées dans Astuce d’import Automerge sans bundler : import des sous-modules /dist/Repo, /dist/AutomergeUrl, etc. au lieu du point d’entrée, et un slim-shim.js local référencé par l’importmap pour rétablir les réexports que l’adaptateur WebSocket attend.

Le service worker et le manifest PWA sont définis inline dans ce fichier plutôt que via des blocs partagés, parce que leur contenu (nom, couleurs, icône, liste d’assets à cacher) est spécifique à l’app.

Retrouver un scrutin après reload

Un scrutin ouvert doit survivre à un rechargement de page, sans perte de bulletins. Le doc Automerge est persisté dans IndexedDB ; au rechargement, le navigateur lit la même URL automerge:... dans la query string et recharge le doc.

def test_persistence_reload(page):
    clear_state(page)
    create_scrutin(page, candidates=["A", "B"], voters=["Alice", "Bob"])
    page.click("#btnTakePhone")
    page.evaluate("window.testForceRanking(['B', 'A'])")
    page.click("#btnSubmit")
    url_before = page.url
    # La sauvegarde IndexedDB est debounced (100 ms) ; on attend qu'elle soit flushée.
    page.wait_for_timeout(300)
    page.reload()
    page.wait_for_selector("[data-app-ready]")
    assert page.url == url_before, f"url changed: {url_before} → {page.url}"
    ballots = page.evaluate("JSON.stringify(window.__voteStore.scrutin.ballots)")
    assert "Alice" in ballots and "B" in ballots and "A" in ballots, f"ballots lost: {ballots}"
    # Après reload on est bien de retour au pass-screen, au tour de Bob
    page.locator(".pass-screen h2").wait_for(state="visible")
    assert "Bob" in page.locator(".pass-screen h2").inner_text()
    print("  PASS: persistence reload")

Rappel : sans avoir cliqué le magic link clk au préalable, l’ami n’a pas le cookie d’auth ni l’sync_url en localStorage et ne peut pas rejoindre la sync. Le lien seul ne suffit pas pour un nouveau contact.

Dérouler un vote complet à deux votants

Golden path : Alice vote, l’écran-tampon apparaît pour Bob, Bob vote, le bouton “Dépouiller” s’active. Le drag-and-drop est piloté via le store (window.testForceRanking) plutôt que via des évènements souris. On teste la logique de classement, pas l’intégration Sortable.

def test_shared_device_flow(page):
    clear_state(page)
    create_scrutin(page, candidates=["A", "B", "C"], voters=["Alice", "Bob"])
    assert "Alice" in page.locator(".pass-screen h2").inner_text()
    page.click("#btnTakePhone")
    page.evaluate("window.testForceRanking(['A', 'C', 'B'])")
    page.click("#btnSubmit")
    assert "Bob" in page.locator(".pass-screen h2").inner_text()
    page.click("#btnTakePhone")
    page.evaluate("window.testForceRanking(['B', 'C', 'A'])")
    page.click("#btnSubmit")
    page.locator("#btnClose").wait_for(state="visible")
    print("  PASS: shared-device flow")

Secret du bulletin : aucun bulletin n’apparaît à l’écran-tampon

Filet de sécurité sur la contrainte de secret : après qu’Alice ait voté, aucun nom de candidat ne doit apparaître dans .pass-screen. Les noms sont masqués par v-show“stage = ‘ballot’"=.

def test_ballot_secrecy(page):
    clear_state(page)
    create_scrutin(page, candidates=["Kebab", "Sushi"], voters=["Alice", "Bob"])
    page.click("#btnTakePhone")
    page.evaluate("window.testForceRanking(['Sushi', 'Kebab'])")
    page.click("#btnSubmit")
    visible = page.locator(".pass-screen").inner_text()
    assert "Kebab" not in visible
    assert "Sushi" not in visible
    print("  PASS: ballot secrecy")

Vérifier un vainqueur de Condorcet strict

def test_condorcet_winner(page):
    # V1: A>B>C, V2: A>C>B, V3: B>A>C
    # A bat B (2-1), A bat C (3-0), B bat C (2-1) → A est vainqueur de Condorcet
    clear_state(page)
    create_scrutin(page, candidates=["A", "B", "C"], voters=["V1", "V2", "V3"])
    for ranking in [["A", "B", "C"], ["A", "C", "B"], ["B", "A", "C"]]:
        page.click("#btnTakePhone")
        page.evaluate(f"window.testForceRanking({ranking})")
        page.click("#btnSubmit")
    page.click("#btnClose")
    assert page.locator(".winner-name").inner_text() == "A"
    assert "strict" in page.locator(".tally-kind").inner_text()
    print("  PASS: Condorcet winner")

Vérifier le tirage randomisé sur un paradoxe

Le paradoxe classique à trois votants, trois candidats : A>B>C, B>C>A, C>A>B. Aucun vainqueur. Smith set = {A, B, C}. Le tirage est déterministe sur le hash des bulletins clos.

def test_random_smith(page):
    clear_state(page)
    create_scrutin(page, candidates=["A", "B", "C"], voters=["V1", "V2", "V3"])
    for ranking in [["A", "B", "C"], ["B", "C", "A"], ["C", "A", "B"]]:
        page.click("#btnTakePhone")
        page.evaluate(f"window.testForceRanking({ranking})")
        page.click("#btnSubmit")
    page.click("#btnClose")
    assert page.locator(".winner-name").inner_text() in ("A", "B", "C")
    assert "Smith" in page.locator(".tally-kind").inner_text()
    print("  PASS: random-smith tiebreak")

Plumbing

Schéma du document Automerge

Un doc par scrutin. Pas de doc racine qui liste tous les scrutins — chaque scrutin vit sous sa propre URL automerge:....

{
  title: string,
  candidates: string[],              // l'ordre de création, immuable
  voters: string[],                  // le roster, immuable après création
  ballots: { voter: string, ranking: string[], at: number }[],
  closed: boolean,
  mode: 'shared-device' | 'per-device',
  method: 'condorcet-random-smith',
  createdAt: number,
}

Un bulletin par votant : un nouveau vote écrase l’ancien en cherchant par voter. Quand on migrera vers un CRDT pour la sync, ce modèle tient tel quel (YArray ou AutomergeList sur ballots).

Repo Automerge, persistance IndexedDB, sync optionnel

Un scrutin = un doc Automerge identifié par son URL automerge:<hash>, portée dans la query string (?doc=automerge:...). L’IndexedDBStorageAdapter garde une copie locale. Le BrowserWebSocketClientAdapter est branché seulement si ?sync_url=wss://... a été fourni (et retenu dans localStorage pour les visites suivantes), pour que les tests et l’usage hors-ligne ne tentent pas de se connecter à rien.

Le serveur de sync est décrit dans Serveur de sync automergesync.

import * as Automerge from '@automerge/automerge';
import { Repo } from 'https://esm.sh/@automerge/automerge-repo@1.2.1/dist/Repo';
import { isValidAutomergeUrl } from 'https://esm.sh/@automerge/automerge-repo@1.2.1/dist/AutomergeUrl';
import { IndexedDBStorageAdapter } from 'https://esm.sh/@automerge/automerge-repo-storage-indexeddb@1';
import { BrowserWebSocketClientAdapter } from 'https://esm.sh/@automerge/automerge-repo-network-websocket@1/dist/BrowserWebSocketClientAdapter';

const WASM_URL = 'https://esm.sh/@automerge/automerge@2.2.9/dist/automerge.wasm';

async function initAutomerge(){
  await Automerge.initializeWasm(fetch(WASM_URL));
}

async function makeRepo(){
  const params = new URLSearchParams(location.search);
  const fromParam = params.get('sync_url');
  if(fromParam){
    localStorage.setItem('condorcet.sync_url', fromParam);
    const clean = new URL(location);
    clean.searchParams.delete('sync_url');
    history.replaceState(null, '', clean);
  }
  const syncUrl = localStorage.getItem('condorcet.sync_url');
  const network = syncUrl ? [new BrowserWebSocketClientAdapter(syncUrl)] : [];
  return new Repo({
    storage: new IndexedDBStorageAdapter('condorcet'),
    network,
  });
}

async function loadInitialHandle(repo){
  const urlParam = new URLSearchParams(location.search).get('doc');
  if(!urlParam || !isValidAutomergeUrl(urlParam)) return null;
  const handle = repo.find(urlParam);
  // On attend au plus 3s pour que le handle soit résolu (typiquement
  // depuis IndexedDB en quelques ms ; plus long si via WebSocket). Si
  // ça dépasse on rend la main : le store s'abonne à =change= et se
  // remplit quand le doc arrive, sans bloquer =data-app-ready=.
  await Promise.race([
    handle.whenReady(['ready', 'unavailable']).catch(() => {}),
    new Promise(r => setTimeout(r, 3000)),
  ]);
  return handle;
}

Astuce d’import Automerge sans bundler

Deux pièges avec esm.sh et Automerge :

  1. @automerge/automerge@2 distribue une version slim. Le WASM n’est pas initialisé automatiquement : on doit appeler Automerge.initializeWasm(fetch(.../automerge.wasm)) avant toute utilisation. On le fait dans initAutomerge() au démarrage.
  2. @automerge/automerge-repo@1 a un point d’entrée par défaut sur esm.sh dont le shim est circulairement vide (un export * from qui boucle). Résultat : Repo, isValidAutomergeUrl et tous les autres exports sont undefined. Le contournement : importer directement les sous-modules compilés (/dist/Repo, /dist/AutomergeUrl).

L’adaptateur WebSocket a en plus une dépendance bundlée vers @automerge/automerge-repo/slim (même shim cassé). L’importmap du fichier HTML remappe cette URL précise vers notre shim local slim-shim.js qui ré-exporte juste NetworkAdapter et cbor depuis les vrais chemins.

Deux fichiers shim à côté d’index.html, ré-exportant ce que les modules bundled d’esm.sh cherchent :

// Shim pour /@automerge/automerge-repo@1.2.1/es2022/slim.mjs.
// Le shim par défaut d'esm.sh est circulairement vide ; on ré-expose
// ici ce dont les adaptateurs bundled ont besoin (NetworkAdapter + cbor).
export { NetworkAdapter } from 'https://esm.sh/@automerge/automerge-repo@1.2.1/dist/network/NetworkAdapter';
import * as cborNs from 'https://esm.sh/@automerge/automerge-repo@1.2.1/dist/helpers/cbor';
export const cbor = cborNs;

Le module fast-sha256 servi par esm.sh n’a qu’un export default (le module CJS n’a pas été explosé en exports nommés). Or storage/keyHash fait import * as sha256; sha256.hash(buf) — qui échoue silencieusement (sha256.hash indéfini), d’où des sauvegardes IndexedDB qui ne persistent rien. Le shim ré-expose hash comme export nommé depuis le default.

import sha256 from 'https://esm.sh/fast-sha256@1.3.0';
export const hash = sha256.hash;
export const HMAC = sha256.HMAC;
export const Hash = sha256.Hash;
export default sha256;

Vérifier la propagation entre deux navigateurs

Le test lance un automerge-repo-sync-server en subprocess (sur ws://localhost:9643), ouvre deux contextes navigateur indépendants sur le même scrutin avec ?sync_url…=, soumet un bulletin dans A, et attend que B le voie apparaître dans son store. Si node/npm ne sont pas disponibles ou que le package ne s’installe pas, le test skip avec un message explicite — il ne bloque pas la suite.

def _goto_robust(page, url, tries=4):
    """Workaround pour =net::ERR_NETWORK_CHANGED= sporadique quand on crée
    plusieurs contextes browser en rafale : on retente le goto si la
    navigation échoue."""
    last = None
    for i in range(tries):
        try:
            page.goto(url, timeout=15000)
            return
        except Exception as e:
            last = e
            if "NETWORK_CHANGED" not in str(e) and "net::ERR_" not in str(e):
                raise
            time.sleep(0.5 * (i + 1))
    raise last

def test_sync_propagation(page):

    fixture = start_sync_server()

            pageB.wait_for_selector("[data-app-ready]", timeout=15000)

Algorithme Condorcet + tie-break seedé

Même algorithme qui sera transcrit en Python dans l’itération “Python interop”. On veut pouvoir vérifier des deux côtés qu’à bulletins identiques on obtient le même vainqueur et la même graine.

function pairwiseMatrix(candidates, ballots){
  const m = {};
  for(const a of candidates){
    m[a] = {};
    for(const b of candidates) if(b !== a) m[a][b] = 0;
  }
  for(const ballot of ballots){
    const pos = {};
    ballot.ranking.forEach((c, i) => { pos[c] = i; });
    for(let i = 0; i < candidates.length; i++){
      for(let j = i+1; j < candidates.length; j++){
        const a = candidates[i], b = candidates[j];
        if(a in pos && b in pos){
          if(pos[a] < pos[b]) m[a][b]++;
          else m[b][a]++;
        }
      }
    }
  }
  return m;
}

function condorcetWinner(candidates, m){
  for(const c of candidates){
    const beatsAll = candidates.every(o => o === c || m[c][o] > m[o][c]);
    if(beatsAll) return c;
  }
  return null;
}

function smithSet(candidates, m){
  // Plus petit ensemble S tel que chaque membre de S bat tout non-membre.
  // On part de l'ensemble complet et on éjecte quiconque est battu par
  // un extérieur qui ne le bat pas en retour.
  let smith = new Set(candidates);
  let changed = true;
  while(changed){
    changed = false;
    for(const c of Array.from(smith)){
      const outsiders = candidates.filter(o => !smith.has(o));
      const beatenByOutside = outsiders.some(o => m[o][c] > m[c][o]);
      if(beatenByOutside){ smith.delete(c); changed = true; }
    }
  }
  return Array.from(smith).sort();
}

async function seedFromBallots(ballots){
  const normalised = ballots
    .map(b => ({voter: b.voter, ranking: b.ranking}))
    .sort((a, b) => a.voter.localeCompare(b.voter));
  const payload = JSON.stringify(normalised);
  const buf = await crypto.subtle.digest('SHA-256', new TextEncoder().encode(payload));
  return new Uint8Array(buf);
}

function mulberry32(seed){
  let a = seed >>> 0;
  return function(){
    a |= 0; a = a + 0x6D2B79F5 | 0;
    let t = Math.imul(a ^ a >>> 15, 1 | a);
    t = t + Math.imul(t ^ t >>> 7, 61 | t) ^ t;
    return ((t ^ t >>> 14) >>> 0) / 4294967296;
  };
}

async function computeTally(scrutin){
  const m = pairwiseMatrix(scrutin.candidates, scrutin.ballots);
  const w = condorcetWinner(scrutin.candidates, m);
  if(w) return { kind: 'condorcet', winner: w, pairwise: m };
  const smith = smithSet(scrutin.candidates, m);
  const seedBytes = await seedFromBallots(scrutin.ballots);
  const seedInt = new DataView(seedBytes.buffer).getUint32(0);
  const rng = mulberry32(seedInt);
  const pick = smith[Math.floor(rng() * smith.length)];
  const seedShort = Array.from(seedBytes.slice(0, 4))
    .map(b => b.toString(16).padStart(2, '0')).join('');
  return { kind: 'random-smith', winner: pick, smith, pairwise: m, seedShort };
}

Store petite-vue — unique source de vérité réactive

Toute la logique de flux vit dans le data du createApp petite-vue. Le scrutin visible est un snapshot du doc Automerge courant : après chaque handle.change(fn) on réassigne store.scrutin = handle.docSync(), ce qui déclenche le rafraîchissement petite-vue via l’assignation. Même chose sur l’évènement change du handle (qui fire aussi après un update via la sync WebSocket). Pas d’observe manuel : une seule source de vérité, un seul point de rafraîchissement.

function shuffled(arr){
  const a = arr.slice();
  for(let i = a.length - 1; i > 0; i--){
    const j = Math.floor(Math.random() * (i + 1));
    [a[i], a[j]] = [a[j], a[i]];
  }
  return a;
}

    this.change(d => {
      const existing = d.ballots.findIndex(b => b.voter === voter);
      const ballot = { voter, ranking, at: Date.now() };
      if(existing >= 0) d.ballots[existing] = ballot;
      else d.ballots.push(ballot);
    });
    this.cancelBallot();
  },

  async close(){
    this.change(d => { d.closed = true; });
    this.tally = await computeTally(this.scrutin);
  },

          .map(li => li.getAttribute('data-candidate'));

      },

  },
