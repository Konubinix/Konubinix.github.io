Pitch et contraintes

Voter à la majorité paraît simple, mais dès qu’il y a plus de deux options la majorité se perd dans les paradoxes. Le scrutin de Condorcet répare ça en regardant chaque duel entre candidats. Quand il n’y a pas de vainqueur net (un cycle), on départage par un tirage au sort dans le Smith set — reproductible, parce que la graine est le hash des bulletins clos, pas un appel serveur.

Cette app est un outil de vote entre amis. Ce n’est pas un système officiel : on peut bidouiller le bulletin du copain en inspectant IndexedDB. Ça suffit pour un apéro ou un choix de film en famille, et ça tient dans un seul fichier HTML.

Les deux modes d’utilisation

L’app supporte deux modes de vote, au choix à la création du scrutin :

  1. Appareil partagé : tout le monde vote sur le même téléphone à tour de rôle. Entre deux votants un écran-tampon masque l’UI et invite à passer le téléphone. Le votant suivant ne voit jamais le classement du précédent.
  2. Un appareil par personne : chacun ouvre le lien du scrutin sur son téléphone et vote séparément. La sync est assurée par le serveur automergesync via WebSocket Automerge. À la place de l’écran-tampon, un écran d’identification laisse chacun choisir son nom dans la liste ; l’identité est mémorisée en localStorage scopée à l’URL du doc, donc un reload ne redemande pas qui on est.

Le mode se choisit à la création et conditionne le flux de vote.

Secret du bulletin

Règle dure : pendant qu’un votant classe ses candidats, il ne voit aucun bulletin déjà soumis. Deux conséquences concrètes :

  • En mode appareil partagé, la liste des candidats à classer est réinitialisée et mélangée pour chaque votant, pour qu’on ne puisse pas reconstruire l’ordre soumis par le précédent à partir de la position initiale.
  • L’écran de vote n’affiche jamais la matrice des duels, les totaux partiels, ni la liste des bulletins. Ces vues n’apparaissent qu’après la clôture du scrutin.

Le compteur “n votants / m inscrits” et la liste des voters ayant déjà voté sont considérés comme non-secrets : ils n’indiquent pas comment ils ont voté. C’est l’opacité sociale minimale acceptable pour un vote entre amis.

Bibliothèques externes

On ne réinvente aucune roue. Les seules briques tierces, toutes chargées via esm.sh dans l’import map :

  • petite-vue — réactivité de l’UI, directives HTML v-show, v-for, v-model, @click. Pas de build step, ~6 KB.

  • Automerge 2 + automerge-repo 1 + automerge-repo-storage-indexeddb

    • automerge-repo-network-websocket — CRDT local-first,

    persistance IndexedDB, sync WebSocket vers le serveur automergesync. Un scrutin = un doc Automerge, identifié par son URL automerge:<hash>, partageable comme lien d’invitation.

  • SortableJS — drag-and-drop pour réordonner les candidats. Framework-agnostic, intégration petite-vue triviale.

  • API Web Crypto native — hash SHA-256 pour la graine de tie-break.

Le WASM d’Automerge n’étant pas chargeable directement depuis le shim par défaut d’esm.sh (la dépendance circulaire du fichier slim.mjs rend les exports vides), on contourne avec deux astuces documentées dans Astuce d’import Automerge sans bundler : import des sous-modules /dist/Repo, /dist/AutomergeUrl, etc. au lieu du point d’entrée, et un slim-shim.js local référencé par l’importmap pour rétablir les réexports que l’adaptateur WebSocket attend.

Le service worker et le manifest PWA sont définis inline dans ce fichier plutôt que via des blocs partagés, parce que leur contenu (nom, couleurs, icône, liste d’assets à cacher) est spécifique à l’app.

Retrouver un scrutin après reload

Un scrutin ouvert doit survivre à un rechargement de page, sans perte de bulletins. Le doc Automerge est persisté dans IndexedDB ; au rechargement, le navigateur lit la même URL automerge:... dans la query string et recharge le doc.

@testcase
def test_persistence_reload(page):
    clear_state(page)
    create_scrutin(page, candidates=["A", "B"], voters=["Alice", "Bob"])
    page.click("#btnTakePhone")
    page.evaluate("window.testForceRanking(['B', 'A'])")
    page.click("#btnSubmit")
    url_before = page.url
    # La sauvegarde IndexedDB est debounced (100 ms) ; on attend qu'elle soit flushée.
    page.wait_for_timeout(300)
    page.reload()
    page.wait_for_selector("[data-app-ready]")
    assert page.url == url_before, f"url changed: {url_before} → {page.url}"
    ballots = page.evaluate("JSON.stringify(window.__voteStore.scrutin.ballots)")
    assert "Alice" in ballots and "B" in ballots and "A" in ballots, f"ballots lost: {ballots}"
    # Après reload on est bien de retour au pass-screen, au tour de Bob
    page.locator(".pass-screen h2").wait_for(state="visible")
    assert "Bob" in page.locator(".pass-screen h2").inner_text()
    print("  PASS: persistence reload")

Réactivité du doc Automerge après reload

Garde-fou pour le fix cloneDoc : un snapshot Automerge sorti de docSync() est enveloppé dans un Proxy (gel/copy-on-write) que petite-vue ne sait pas refaire réagir après un reload. Conséquence observée : après rechargement d’un scrutin pré-existant, un nouveau bulletin soumis ne mettait plus à jour les bindings sur scrutin.ballots.length (le compteur n/m, la close-bar, l’écran de tally restaient figés). Le fix : cloner en JSON plat dans change() et dans le listener change du handle. Ce test soumet un bulletin, reload, soumet le bulletin suivant, et vérifie que le compteur affiché dans l’UI reflète bien le nouveau total.

@testcase
def test_reload_reactivity(page):
    clear_state(page)
    create_scrutin(page, candidates=["A", "B"], voters=["Alice", "Bob"])
    page.click("#btnTakePhone")
    page.evaluate("window.testForceRanking(['A', 'B'])")
    page.click("#btnSubmit")
    page.wait_for_timeout(300)  # flush debounced IndexedDB save
    counter_before = page.locator(".pass-screen .counter").inner_text()
    assert "1" in counter_before and "2" in counter_before, f"pre-reload: {counter_before}"
    page.reload()
    page.wait_for_selector("[data-app-ready]")
    page.locator(".pass-screen h2").wait_for(state="visible")
    # Le doc est rehydraté depuis IndexedDB → scrutin ré-assigné après mount.
    # Sans clone, les lectures imbriquées ne se rafraîchissent plus.
    page.click("#btnTakePhone")
    page.evaluate("window.testForceRanking(['B', 'A'])")
    page.click("#btnSubmit")
    # Ici la close-bar doit apparaître (dépend de scrutin.ballots.length réactif).
    page.locator("#btnClose").wait_for(state="visible", timeout=5000)
    counter_after = page.locator(".pass-screen .counter").inner_text()
    assert "2" in counter_after, f"counter didn't update after reload: {counter_after}"
    print("  PASS: reload reactivity")

Extension du store pour le partage : URL courante, sheet natif navigator.share avec fallback clipboard, génération QR via la lib chargée dans l’importmap.

Object.assign(voteStore.ui, {
    qrOpen: false,
    qrSvg: '',
    shareUrl: '',
    shareToast: '',
});

Object.assign(voteStore, {
    currentShareUrl(){
        return location.origin + location.pathname + location.search;
    },

    async shareScrutin(){
        const url = this.currentShareUrl();
        const title = (this.scrutin && this.scrutin.title) || 'Scrutin';
        if(navigator.share){
            try { await navigator.share({ title, url }); return; }
            catch(e){ /* annulé ou non supporté → fallback clipboard */ }
        }
        try {
            await navigator.clipboard.writeText(url);
            this.ui.shareToast = 'Lien copié';
            setTimeout(() => { this.ui.shareToast = ''; }, 2000);
        } catch(e){
            this.ui.shareToast = 'Copie impossible';
            setTimeout(() => { this.ui.shareToast = ''; }, 2000);
        }
    },

    openQR(){
        const url = this.currentShareUrl();
        const qr = window.qrcode(0, 'M');
        qr.addData(url);
        qr.make();
        this.ui.qrSvg = qr.createSvgTag({ cellSize: 6, margin: 2 });
        this.ui.shareUrl = url;
        this.ui.qrOpen = true;
    },
});

Extension du store pour le cycle de vote : l’état du bulletin en cours (currentVoter, ui.ranking), les actions startBallot / cancelBallot / submitBallot et l’intégration SortableJS. Ces actions sont aussi consommées par le mode per-device (chooseIdentity appelle startBallot), mais vivent ici parce que le template ballot-screen qu’elles pilotent est dans cette section.

cancelBallot ramène au point d’entrée du mode : pass-screen en partagé ; en per-device on oublie aussi l’identité (clé localStorage effacée) pour laisser re-choisir un nom sur l’identity-screen.

Intégration Sortable : Vue reste seule source de vérité. SortableJS mute le DOM pendant le drag : il déplace physiquement le <li> tiré vers sa nouvelle position. Si on laisse cette mutation tenir, le virtual DOM de petite-vue se désynchronise du DOM réel, et la réconciliation suivante (au prochain rendu du v-for) laisse des <li> résiduels — un votant suivant voit alors plus d’items que de candidats. Le pattern canonique utilisé par vuedraggable : dans onEnd, on révoque la mutation de Sortable (on replace le <li> à son oldIndex), puis on met à jour le store.     const a = arr.slice();
    for(let i = a.length - 1; i > 0; i--){
        const j = Math.floor(Math.random() * (i + 1));
        [a[i], a[j]] = [a[j], a[i]];
    }
    return a;
}

Dépouiller

Une fois le scrutin clos, l’écran de dépouillement montre : la matrice des duels, le vainqueur de Condorcet s’il existe, ou le Smith set et le candidat tiré au sort (avec mention de la graine). La narration explique ce qu’on regarde — c’est là que Condorcet s’apprend en le pratiquant.

Vote par classements → duels pairwise. Chaque bulletin donne, pour tout couple (A, B), sa préférence locale. On agrège en une matrice pairwise[A][B] = nombre de votants qui mettent A avant B dans leur classement. Dire que A bat B en duel, c’est pairwise[A][B] > pairwise[B][A]. La matrice complète de ces duels, c’est ce qu’affiche l’écran de dépouillement.

Un vainqueur de Condorcet est un candidat qui bat tous les autres en duel. C’est l’idéal démocratique : quel que soit le challenger qu’on lui oppose, la majorité le préfère. Quand il existe, on a fini. La fonction condorcetWinner le cherche par scan linéaire.

Mais ce vainqueur peut ne pas exister. Le paradoxe de Condorcet, classique à trois votants :

votant classement
V1 A > B > C
V2 B > C > A
V3 C > A > B

Duels : A bat B (V1, V3 préfèrent A, V2 préfère B → 2-1), B bat C (2-1), C bat A (2-1). Chaque candidat en bat un et est battu par un autre : la préférence majoritaire est intransitive. Il n’y a pas de “meilleur” au sens de Condorcet — il faut donc une règle de secours.

La règle de secours consulte le Smith set : le plus petit ensemble non-vide S tel que chaque membre de S bat (en duel) chaque candidat extérieur à S. Autrement dit, la “short-list” des candidats qui restent sérieusement en course après qu’on a exclu ceux qu’une majorité préfère à un autre finaliste. Propriétés utiles :

  • Quand un vainqueur de Condorcet existe, le Smith set vaut {vainqueur}. Le cas général englobe donc le cas strict.
  • Dans le paradoxe ci-dessus, le Smith set vaut {A, B, C} : chacun des trois en bat un autre, aucun n’est dominé par un extérieur (il n’y en a pas).
  • Si on ajoute un quatrième candidat D battu par les trois du cycle, le Smith set reste {A, B, C} et D en est exclu — D n’a pas voix au tirage.

La construction de smithSet part de l’ensemble complet et itère : à chaque passe on éjecte tout membre battu par au moins un extérieur courant, jusqu’à point fixe. Le résultat est par définition le plus petit ensemble dominant.

Dans le Smith set, il faut encore départager. Math.random() suffirait techniquement, mais alors le dépouillement ne serait pas vérifiable : personne ne pourrait, après coup, confirmer que l’app n’a pas triché. On tire donc au sort avec une graine reproductible : SHA-256(bulletins triés par nom de votant). À bulletins identiques, même graine, même vainqueur. Le résultat reste aléatoire mais reproductible — n’importe qui ayant accès aux bulletins peut recalculer, en JS ou en Python, et confirmer le tirage. Les quatre premiers octets de la graine sont affichés au dépouillement pour qu’on puisse citer “le tirage abcd1234”.

Le même algorithme sera transcrit en Python dans l’itération “Python interop” : à bulletins identiques on doit obtenir des deux côtés le même vainqueur et la même graine.

function pairwiseMatrix(candidates, ballots){
    const m = {};
    for(const a of candidates){
        m[a] = {};
        for(const b of candidates) if(b !== a) m[a][b] = 0;
    }
    for(const ballot of ballots){
        const pos = {};
        ballot.ranking.forEach((c, i) => { pos[c] = i; });
        for(let i = 0; i < candidates.length; i++){
            for(let j = i+1; j < candidates.length; j++){
                const a = candidates[i], b = candidates[j];
                if(a in pos && b in pos){
                    if(pos[a] < pos[b]) m[a][b]++;
                    else m[b][a]++;
                }
            }
        }
    }
    return m;
}

function condorcetWinner(candidates, m){
    for(const c of candidates){
        const beatsAll = candidates.every(o => o === c || m[c][o] > m[o][c]);
        if(beatsAll) return c;
    }
    return null;
}

function smithSet(candidates, m){
    let smith = new Set(candidates);
    let changed = true;
    while(changed){
        changed = false;
        for(const c of Array.from(smith)){
            const outsiders = candidates.filter(o => !smith.has(o));
            const beatenByOutside = outsiders.some(o => m[o][c] > m[c][o]);
            if(beatenByOutside){ smith.delete(c); changed = true; }
        }
    }
    return Array.from(smith).sort();
}

async function seedFromBallots(ballots){
    const normalised = ballots
          .map(b => ({voter: b.voter, ranking: b.ranking}))
          .sort((a, b) => a.voter.localeCompare(b.voter));
    const payload = JSON.stringify(normalised);
    const buf = await crypto.subtle.digest('SHA-256', new TextEncoder().encode(payload));
    return new Uint8Array(buf);
}

function mulberry32(seed){
    let a = seed >>> 0;
    return function(){
        a |= 0; a = a + 0x6D2B79F5 | 0;
        let t = Math.imul(a ^ a >>> 15, 1 | a);
        t = t + Math.imul(t ^ t >>> 7, 61 | t) ^ t;
        return ((t ^ t >>> 14) >>> 0) / 4294967296;
    };
}

async function computeTally(scrutin){
    const m = pairwiseMatrix(scrutin.candidates, scrutin.ballots);
    const w = condorcetWinner(scrutin.candidates, m);
    if(w) return { kind: 'condorcet', winner: w, pairwise: m };
    const smith = smithSet(scrutin.candidates, m);
    const seedBytes = await seedFromBallots(scrutin.ballots);
    const seedInt = new DataView(seedBytes.buffer).getUint32(0);
    const rng = mulberry32(seedInt);
    const pick = smith[Math.floor(rng() * smith.length)];
    const seedShort = Array.from(seedBytes.slice(0, 4))
          .map(b => b.toString(16).padStart(2, '0')).join('');
    return { kind: 'random-smith', winner: pick, smith, pairwise: m, seedShort };
}

Schéma du document Automerge

Un doc par scrutin. Pas de doc racine qui liste tous les scrutins — chaque scrutin vit sous sa propre URL automerge:....

Repo Automerge, persistance IndexedDB, sync optionnel

Un scrutin = un doc Automerge identifié par son URL automerge:<hash>, portée dans la query string (?doc=automerge:...). L’IndexedDBStorageAdapter garde une copie locale. Le BrowserWebSocketClientAdapter est branché seulement si ?sync_url=wss://... a été fourni (et retenu dans localStorage pour les visites suivantes), pour que les tests et l’usage hors-ligne ne tentent pas de se connecter à rien.

Le serveur de sync est décrit dans Serveur de sync automergesync.

loadInitialHandle ne bloque pas plus de 3s sur whenReady : typiquement le doc remonte d’IndexedDB en quelques ms, mais via WebSocket il peut tarder davantage. Si le timeout expire on rend la main sans bloquer data-app-ready ; le store s’abonne ensuite à l’évènement change et se remplira quand le doc arrivera.

import * as Automerge from '@automerge/automerge';
import { Repo } from 'https://esm.sh/@automerge/automerge-repo@1.2.1/dist/Repo';
import { isValidAutomergeUrl } from 'https://esm.sh/@automerge/automerge-repo@1.2.1/dist/AutomergeUrl';
import { IndexedDBStorageAdapter } from 'https://esm.sh/@automerge/automerge-repo-storage-indexeddb@1';
import { BrowserWebSocketClientAdapter } from 'https://esm.sh/@automerge/automerge-repo-network-websocket@1/dist/BrowserWebSocketClientAdapter';

const WASM_URL = 'https://esm.sh/@automerge/automerge@2.2.9/dist/automerge.wasm';

async function initAutomerge(){
    await Automerge.initializeWasm(fetch(WASM_URL));
}

async function makeRepo(){
    const params = new URLSearchParams(location.search);
    const fromParam = params.get('sync_url');
    if(fromParam){
        localStorage.setItem('condorcet.sync_url', fromParam);
        const clean = new URL(location);
        clean.searchParams.delete('sync_url');
        history.replaceState(null, '', clean);
    }
    const syncUrl = localStorage.getItem('condorcet.sync_url');
    const network = syncUrl ? [new BrowserWebSocketClientAdapter(syncUrl)] : [];
    return new Repo({
        storage: new IndexedDBStorageAdapter('condorcet'),
        network,
    });
}

async function loadInitialHandle(repo){
    const urlParam = new URLSearchParams(location.search).get('doc');
    if(!urlParam || !isValidAutomergeUrl(urlParam)) return null;
    const handle = repo.find(urlParam);
    await Promise.race([
        handle.whenReady(['ready', 'unavailable']).catch(() => {}),
        new Promise(r => setTimeout(r, 3000)),
    ]);
    return handle;
}

Astuce d’import Automerge sans bundler

Deux pièges avec esm.sh et Automerge :

  1. @automerge/automerge@2 distribue une version slim. Le WASM n’est pas initialisé automatiquement : on doit appeler Automerge.initializeWasm(fetch(.../automerge.wasm)) avant toute utilisation. On le fait dans initAutomerge() au démarrage.
  2. @automerge/automerge-repo@1 a un point d’entrée par défaut sur esm.sh dont le shim est circulairement vide (un export * from qui boucle). Résultat : Repo, isValidAutomergeUrl et tous les autres exports sont undefined. Le contournement : importer directement les sous-modules compilés (/dist/Repo, /dist/AutomergeUrl).

L’adaptateur WebSocket a en plus une dépendance bundlée vers @automerge/automerge-repo/slim (même shim cassé). L’importmap du fichier HTML remappe cette URL précise vers notre shim local slim-shim.js qui ré-exporte juste NetworkAdapter et cbor depuis les vrais chemins.

Deux fichiers shim à côté d’index.html, ré-exportant ce que les modules bundled d’esm.sh cherchent :

// Shim pour /@automerge/automerge-repo@1.2.1/es2022/slim.mjs.
// Le shim par défaut d'esm.sh est circulairement vide ; on ré-expose
// ici ce dont les adaptateurs bundled ont besoin (NetworkAdapter + cbor).
export { NetworkAdapter } from 'https://esm.sh/@automerge/automerge-repo@1.2.1/dist/network/NetworkAdapter';
import * as cborNs from 'https://esm.sh/@automerge/automerge-repo@1.2.1/dist/helpers/cbor';
export const cbor = cborNs;

Le module fast-sha256 servi par esm.sh n’a qu’un export default (le module CJS n’a pas été explosé en exports nommés). Or storage/keyHash fait import * as sha256; sha256.hash(buf) — qui échoue silencieusement (sha256.hash indéfini), d’où des sauvegardes IndexedDB qui ne persistent rien. Le shim ré-expose hash comme export nommé depuis le default.

import sha256 from 'https://esm.sh/fast-sha256@1.3.0';
export const hash = sha256.hash;
export const HMAC = sha256.HMAC;
export const Hash = sha256.Hash;
export default sha256;

Serveur de sync automergesync

Serveur basé sur le package npm officiel @automerge/automerge-repo-sync-server, packagé dans l’image Docker konubinix/automergesync. Pour activer la sync dans l’app, on ouvre une fois l’URL avec ?sync_url=wss://<ton-serveur> ; la valeur est mémorisée dans localStorage et réutilisée aux visites suivantes.

Fixture de test co-localisée ici : on réutilise la même image Docker pour que les tests tournent contre le même binaire qu’en prod. Le container est démarré au premier test qui en a besoin et stoppé via atexit (partagé entre les tests sync). Chaque test utilise des repo.find/create avec des URLs de doc uniques → pas d’interférence.

require_sync_server encapsule le pattern “start ou skip” ; two_contexts la paire de contextes navigateur fermés en sortie de with. BALLOTS_JSON est le JS probe partagé par les deux tests qui lisent scrutin.ballots via window.__voteStore.

import atexit, contextlib, shutil, socket, subprocess, tempfile, time, uuid
SYNC_IMAGE = "konubinix/automergesync:0.1.0"
_sync_state = {"fixture": None, "tried": False}

BALLOTS_JSON = ("JSON.stringify((window.__voteStore.scrutin && "
                "window.__voteStore.scrutin.ballots) || [])")

def _free_port():
    with socket.socket(socket.AF_INET, socket.SOCK_STREAM) as s:
        s.bind(("127.0.0.1", 0))
        return s.getsockname()[1]

def start_sync_server():
    """Return (container, data_dir, sync_url) or None. Cached across calls."""
    if _sync_state["fixture"] is not None:
        return _sync_state["fixture"]
    if _sync_state["tried"]:
        return None
    _sync_state["tried"] = True
    if not shutil.which("docker"):
        return None
    data_dir = tempfile.mkdtemp(prefix="amr-sync-data-")
    container = f"condorcet-sync-{uuid.uuid4().hex[:8]}"
    port = _free_port()
    try:
        subprocess.check_call(
            ["docker", "run", "-d", "--rm",
             "--name", container,
             "-p", f"127.0.0.1:{port}:3030",
             "-e", "PORT=3030",
             "-e", "DATA_DIR=/data",
             "-v", f"{data_dir}:/data",
             SYNC_IMAGE,
             "automerge-repo-sync-server"],
            stdout=subprocess.DEVNULL, stderr=subprocess.DEVNULL,
        )
    except subprocess.CalledProcessError:
        shutil.rmtree(data_dir, ignore_errors=True)
        return None
    import urllib.request, urllib.error
    for _ in range(200):
        try:
            urllib.request.urlopen(f"http://localhost:{port}/", timeout=0.5).close()
            _sync_state["fixture"] = (container, data_dir, f"ws://localhost:{port}")
            atexit.register(_stop_sync_server_atexit)
            return _sync_state["fixture"]
        except (urllib.error.URLError, ConnectionError, TimeoutError, OSError):
            time.sleep(0.1)
    subprocess.run(["docker", "stop", container],
                   stdout=subprocess.DEVNULL, stderr=subprocess.DEVNULL)
    shutil.rmtree(data_dir, ignore_errors=True)
    return None

def require_sync_server(name):
    """Renvoie le =sync_url= ou None après avoir printé le SKIP."""
    fixture = start_sync_server()
    if fixture is None:
        print(f"  SKIP: {name} (docker unavailable)")
        return None
    return fixture[2]

@contextlib.contextmanager
def two_contexts(browser, viewport={"width": 400, "height": 800}):
    """Paire de contextes navigateur, fermés en sortie du =with=."""
    ctxA = browser.new_context(viewport=viewport)
    ctxB = browser.new_context(viewport=viewport)
    try:
        yield ctxA, ctxB
    finally:
        ctxA.close()
        ctxB.close()

def _stop_sync_server_atexit():
    fx = _sync_state.get("fixture")
    if not fx:
        return
    container, data_dir, _ = fx
    subprocess.run(["docker", "stop", container],
                   stdout=subprocess.DEVNULL, stderr=subprocess.DEVNULL)
    shutil.rmtree(data_dir, ignore_errors=True)
    _sync_state["fixture"] = None

Toute la logique de flux vit dans le data du createApp petite-vue. Le scrutin visible est un snapshot du doc Automerge courant : après chaque handle.change(fn) on réassigne store.scrutin = handle.docSync(), ce qui déclenche le rafraîchissement petite-vue via l’assignation. Même chose sur l’évènement change du handle (qui fire aussi après un update via la sync WebSocket). Pas d’observe manuel : une seule source de vérité, un seul point de rafraîchissement.

Trois frictions dans l’intégration Automerge + petite-vue justifient quelques rigidités :

  • docSync() d’Automerge renvoie un objet enveloppé dans son propre Proxy (gel / copy-on-write) que petite-vue ne sait pas refaire réagir proprement. Après reload, les bindings sur propriétés imbriquées (scrutin.closed, scrutin.ballots.length) ne se rafraîchissaient pas quand on ré-assignait scrutin. cloneDoc stringifie vers du JSON plat que la réactivité Vue enveloppe sans surprise.
  • Le Repo et son DocHandle vivent hors du store réactif. Petite-vue enveloppe le data dans un Proxy, ce qui casse les private fields (#) de la classe Repo (“Receiver must be an instance of…”). On garde _repo et _handle en module-level et on n’expose au store qu’un snapshot du doc, déjà plain JSON.
  • allVoted est un flag plat recalculé à chaque mutation (syncFlags) plutôt qu’un getter. Même cause que cloneDoc : après reload, les getters sur scrutin.ballots.length ne se retraçaient plus.

nextVoter, rosterCount, ballotsCount restent des getters, eux : ils lisent scrutin lui-même, que la ré-assignation de change() suffit à faire re-lire. Un getter petite-vue ne doit cependant pas retourner un Set ou Map — la réactivité tente de les proxifier et échoue (“non-object as target”).

attach(handle) est tolérant au handle pas-encore-ready : docSync() peut être undefined si le doc n’a pas fini de remonter d’IndexedDB ou de la sync. Le listener change remplit this.scrutin quand ça arrive. initStage dispatche au bon stage initial : directement 'pass' pour le mode partagé, ou via l’extension per-device qui définit initStagePerDevice.

function cloneDoc(doc){
    return doc ? JSON.parse(JSON.stringify(doc)) : doc;
}

let _repo = null;
let _handle = null;

const voteStore = {
    scrutin: null,
    tally: null,
    stage: 'pass',       // 'pass' | 'ballot' | 'identify' | 'waiting'
    allVoted: false,
    ui: {},

    get rosterCount(){ return this.scrutin ? this.scrutin.voters.length : 0; },
    get ballotsCount(){ return this.scrutin ? this.scrutin.ballots.length : 0; },
    get nextVoter(){
        if(!this.scrutin) return null;
        const voted = {};
        for(const b of this.scrutin.ballots) voted[b.voter] = true;
        return this.scrutin.voters.find(v => !voted[v]) || null;
    },

    change(fn){
        _handle.change(fn);
        this.scrutin = cloneDoc(_handle.docSync());
        this.syncFlags();
    },

    syncFlags(){
        const s = this.scrutin;
        this.allVoted = !!s && s.ballots.length >= s.voters.length;
    },

    attach(handle){
        _handle = handle;
        const doc = handle.docSync();
        if(doc){
            this.scrutin = cloneDoc(doc);
            this.syncFlags();
            if(doc.closed) computeTally(doc).then(t => { this.tally = t; });
            this.initStage(doc);
        } else {
            this.stage = 'pass';
        }
        handle.on('change', ev => {
            this.scrutin = cloneDoc(ev.doc);
            this.syncFlags();
            if(ev.doc.closed && !this.tally){
                computeTally(ev.doc).then(t => { this.tally = t; });
            }
        });
    },

    initStage(doc){
        if(doc.mode === 'per-device') this.initStagePerDevice(doc);
        else this.stage = 'pass';
    },
};

Initialisation au chargement

On monte l’app petite-vue une fois les dépendances Automerge prêtes. createApp(voteStore).mount('body') active les directives v-* du DOM et lie voteStore aux templates.

On enveloppe d’abord voteStore dans reactive() explicitement et on appelle attach() sur ce proxy. Sinon, les callbacks async capturés dans attach (le .then() de computeTally, le listener handle.on('change', ...)) referment sur this = voteStore raw ; leurs écritures post-mount contournent alors le Proxy petite-vue et ne notifient pas les templates. Le bug observable : après un reload sur un scrutin clos, le tally se calcule bien mais le v-if“tally”= ne re-rend pas. reactive() est idempotent (WeakMap), donc le createApp(reactiveStore) réutilise le même proxy.
