Check Whether Storage Drive Is Dying or Not

Fleeting

authorship
this note is edited using Claude/default, governed by the note how to write a literature note
tl;dr
smartctl -x prints what a drive reports about itself, smartctl -t short and -t long start its self-tests, its normalized attributes are compared with the values at which its maker advises replacing it, and the attributes are read again after a big write.
what
note showing the method to analyse how healthy a storage drive is
what
using run/media/sam/surface as guinea pig

Reading what the drive reports about itself

how
smartctl -x « prints all SMART and non-SMART information about the device »1.

Running the self-tests

how
smartctl -t short runs the drive’s short self-test2.
how
smartctl -t long starts the drive’s extended self-test3.
how
both commands can be given while the system runs, unless run in captive mode4.
how
smartctl -l xselftest prints the log of the drive’s self-tests5.

Comparing the attributes to the maker’s criterion

how
the normalized attributes are compared with the values at which the drive’s maker advises replacing it.
example
in a paper on enterprise workloads6, Samsung advises replacing a drive once any of the normalized values of attributes 179, 181, 182 and 183 drops below 107.

Reading the attributes before and after a big write

how
the attributes are read before and after a big write, and compared.
example
Samsung’s procedure for estimating endurance reads « Record initial SMART attributes », then « Run the test », then « Record final SMART attributes »8.

Surface as the guinea pig

example
the partition mounted on /run/media/sam/surface.

findmnt -no SOURCE /run/media/sam/surface

/dev/sda1
example
its drive reports normalized values 99, 100, 100 and 99 for attributes 179, 181, 182 and 1839.
  • therefore: if this drive’s attributes mean what Samsung’s paper says, its criterion does not call for replacing surface’s drive.
    • scope: the paper does not name this model.
example
its drive reports normalized value 87 for attribute 1779.
  • what: Samsung’s paper defines that normalized value as the « Percentage of remaining P/E cycles »10.
  • therefore: if that definition holds for this drive, 87 % of its P/E cycles remain.
example
its drive’s self-test log lists a « Short offline » test « Completed without error »11.
example
between readings taken just before and just after copying a folder onto surface, the raw value of attribute 241 rose from 27760565674 to 27768495544, and the raw values of attributes 181, 182 and 183 stayed at 0, 0 and 312, 13.
  • therefore: if these attributes mean what Samsung’s paper says, its drive counted no new program fail, erase fail or runtime bad block across that copy.
example
its drive’s report, once an extended self-test has completed.

smartctl -x /dev/sda
