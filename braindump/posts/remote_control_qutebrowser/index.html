Giving AI agents partial access to my running qutebrowser

why
so those agents can help me investigate issues.
what
partial means I grant seeing and interacting apart.
rule
a solution that leaves how qutebrowser is launched unchanged is preferred.
  • scope: opening its DevTools port, which needs such a change, is the fallback.
how
the agent’s tools come from a small MCP server that sends commands to the socket a running qutebrowser listens on1, with seeing and interacting in separate tools.

Stories

Getting help on a payment page, then on an AWS page

rule
this story asserts that the agent sees the page and that it interacts with it through separate tools.
On a payment page
what
I am on a payment page.

open_page("payment.html")
what
I share it with an agent, letting it see only.

agent = await share()
what
the agent explains a line of the page.

dom = (await agent.call("read_dom")).content[0].text
assert "Total: 42.00 €" in dom, f"the payment page the agent reads lacks its total: {dom}"
what
unasked, the agent tries to click « Pay », and my harness refuses it.

with pytest.raises(Refused):
    await agent.call("click", {"selector": "button"})
assert not pages.paid.is_set(), "« Pay » was clicked"
Then on an AWS page
what
I land on an AWS page, trying to configure something boring.
  • example: an AgentCore Bedrock MCP.

open_page("aws.html")
what
I let the agent interact too.

agent.grant_all()
what
the agent tells me what the field I name currently holds.

dom = (await agent.call("read_dom")).content[0].text
region = re.search(r'<input name="region" value="([^"]*)"', dom)
assert region and region[1] == "us-east-1", f"the region the agent reads is not us-east-1: {dom}"
what
the agent helps me grasp the meaning of the buttons, forms and obscure concepts on that page.

it takes a screenshot of the page.

shot = (await agent.call("screenshot")).content[0]
image = PIL.Image.open(io.BytesIO(base64.b64decode(shot.data))).convert("RGB")
assert AWS_ORANGE in image.getdata(), "the screenshot the agent sees lacks the page's orange band"

once I grasp the field, the agent fills it, then clicks « Save ».

await agent.call("click", {"selector": "button"})
dom = (await agent.call("read_dom")).content[0].text
saved = re.search(r'<output id="saved">([^<]*)</output>', dom)

How the stories are tested

rule
a test runs each story, calling the tools the agent would use rather than driving a real agent.
  • scope: it reaches those tools, not the wiring of a real agent to them, which stays unmeasured.
  • how: it plays my harness too: it calls only the tools granted so far, and refuses a call to any other.
    • how: at first it grants only the tools the server marks read-only.
rule
the story’s test runs against pages served for it, rather than a real payment page or AWS page.

  • why: an AWS page needs my account and changes under the test, where a served page gives the same run each time.

  • example: a payment page whose total reads « Total: 42.00 € », with a « Pay » button.

    <!doctype html>
<meta charset="utf-8">
<title>Payment page</title>
<body onload="document.querySelector('#total').textContent = 'Total: 42.00 €'; fetch('/loaded')">
  <p id="total"></p>
  <button onclick="fetch('/paid')">Pay</button>
</body>

  • example: a form whose field holds « us-east-1 », with a « Save » button, under an orange band, which writes what it saves into the page.

    <!doctype html>
<title>AWS page</title>
<body onload="document.querySelector('#band').style.background = '#ff9900';
              document.querySelector('[name=region]').setAttribute('value', 'us-east-1'); fetch('/loaded')">
  <div id="band" style="height: 50px"></div>
  <form onsubmit="document.querySelector('#saved').textContent = this.region.value;
                  return false">
    <label>Region <input name="region"></label>
    <button>Save</button>
    <output id="saved"></output>
  </form>
</body>
rule
a dagger function runs the tests in a docker container whose image dagger builds, with qutebrowser under Xvfb.
rule
the tests are written in Python, run by pytest, and reach the tools through the MCP Python SDK.
rule
the qutebrowser a test starts has a fresh base directory, holding none of my config.

Promises

The agent sees the page I have open

what
as I see it, and its DOM.
therefore
the story passing entails the tools let the agent see the page, since through them the test reads what the payment page’s total and the AWS field currently hold.
therefore
it also entails the tools let the agent see the page as I see it, since through them the test finds the page’s orange band among the pixels of a screenshot.

The agent interacts with that page

what
using tools separate from those that let it see it.
  • why: so my agent harness can grant the one and refuse the other.
rule
granting and refusing is the harness’s work, not these tools'.
  • why: the harness is what provides security, and I do not reinvent it.
therefore
the story passing entails the server marks no click tool read-only, since the harness, granting only the tools so marked, refuses the click and « Pay » stays unclicked.
scope
a tool marked read-only that still acts on the page would pass unseen.
scope
filling and clicking « Save » are not tested yet.

The server

what
that server is the clk command qutebrowser-mcp.
how
it finds that socket where qutebrowser puts it: under my runtime directory, named after my user2.

def send(command):
    runtime = pathlib.Path(os.environ.get("XDG_RUNTIME_DIR", f"/run/user/{os.getuid()}")) / "qutebrowser"
    name = hashlib.md5(getpass.getuser().encode()).hexdigest()
    with socket.socket(socket.AF_UNIX) as ipc:
        ipc.connect(str(runtime / f"ipc-{name}"))
        ipc.sendall((json.dumps({"args": [command], "target_arg": None, "protocol_version": 1}) + "\n").encode())
how
to see the page, it has qutebrowser hand the page to a small script, which copies it where the server reads it back, looking every tenth of a second and giving up after ten.
how
it marks the tools that see as read-only, so a harness can grant them by that mark alone.

HAND_OVER_WAIT = 10  # seconds
HAND_OVER_POLL = 0.1  # seconds


def wait_for(path):
    deadline = time.monotonic() + HAND_OVER_WAIT
    while not path.exists():
        if time.monotonic() > deadline:
            raise TimeoutError(f"qutebrowser never handed {path.name} over")
        time.sleep(HAND_OVER_POLL)


@server.tool(annotations=ToolAnnotations(readOnlyHint=True))
def read_dom() -> str:
    """The DOM of the page qutebrowser shows, as HTML."""
    with tempfile.TemporaryDirectory() as tmp:
        dom, script = pathlib.Path(tmp) / "dom.html", pathlib.Path(tmp) / "hand-over"
        script.write_text('#!/bin/sh\ncp "$QUTE_HTML" "$1.part" && mv "$1.part" "$1"\n')
        script.chmod(0o755)
        send(f":spawn --userscript {script} {dom}")
        wait_for(dom)
        return dom.read_text()
how
to show the page as I see it, it has qutebrowser save a screenshot, and reads the image back the same way.

@server.tool(annotations=ToolAnnotations(readOnlyHint=True))
def screenshot() -> Image:
    """What qutebrowser shows of the page, as a PNG."""
    with tempfile.TemporaryDirectory() as tmp:
        shot = pathlib.Path(tmp) / "shot.png"
        send(f":screenshot {shot}")
        wait_for(shot)
        return Image(data=shot.read_bytes(), format="png")
how
to interact, it has qutebrowser click the element a selector picks; to fill a field, it has the page focus it and select what it holds, then types the new text over it.

@server.tool()
def click(selector: str) -> str:
    """Click the element SELECTOR picks."""
    send(f":click-element css {selector}")
    return f"clicked {selector}"


@server.tool()
def fill(selector: str, text: str) -> str:
    """Put TEXT in the field SELECTOR picks, in place of what it held."""
    field = f"document.querySelector({json.dumps(selector)})"
    send(f":jseval --quiet {field}.focus(); {field}.select()")
    send(f":insert-text {text}")
    return f"filled {selector}"
