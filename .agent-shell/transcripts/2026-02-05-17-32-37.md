No, that won't work. CORS headers control fetch/XHR requests, but the `Worker()` constructor has a stricter same-origin policy — it requires the script to be from the **same origin** as the page. CORS headers don't relax this restriction for `new Worker()`.

Your options are:

1. **Host the worker script on the same origin** (`sam.konubinix.eu`) — the most straightforward fix.

2. **Fetch + Blob workaround** — fetch the cross-origin script, create a Blob URL, and pass that to `new Worker()`:
   ```js
   fetch('https://ipfs.konubinix.eu/p/.../load_stl.min.js')
     .then(r => r.blob())
     .then(blob => {
       const worker = new Worker(URL.createObjectURL(blob));
     });
   ```
   This requires the IPFS server to send proper CORS headers for the fetch to succeed (e.g., `Access-Control-Allow-Origin: https://sam.konubinix.eu`).

3. **Use `type: 'module'` with `import()`** — in some browsers, `new Worker(url, { type: 'module' })` relaxes the same-origin check, but support is inconsistent.

That's understandable. Then the Fetch + Blob workaround is your best bet. The idea:

1. The page fetches the worker script cross-origin (this works if the IPFS gateway sends CORS headers, which most public IPFS gateways do).
2. It creates a Blob URL from the response — which is same-origin.
3. It patches the STL viewer to use that Blob URL for the Worker.

The problem is that `stl_viewer.min.js` internally calls `new Worker(...)` with a hardcoded/relative path, and you can't easily patch a minified third-party script.

A practical approach: **intercept the `Worker` constructor** before loading the STL viewer script. Something like:

```html
<script>
const OriginalWorker = Worker;
const stlBase = 'https://ipfs.konubinix.eu/p/bafybeickotxpnjv4qye2fbkk5e7q4edk563tpxjca7svcxgj2nbom4c7oa/';
Worker = function(url, opts) {
  if (typeof url === 'string' && url.startsWith(stlBase)) {
    return fetch(url)
      .then(r => r.blob())
      .then(blob => new OriginalWorker(URL.createObjectURL(blob), opts))
  }
  return new OriginalWorker(url, opts);
};
</script>
<script src="https://ipfs.konubinix.eu/p/bafybeickotxpnjv4qye2fbkk5e7q4edk563tpxjca7svcxgj2nbom4c7oa/stl_viewer.min.js"></script>
```

The catch: the `Worker` constructor is normally synchronous (returns a Worker immediately), but the fetch is async. So if the STL viewer code immediately calls `worker.postMessage(...)` after construction, it will fail because the proxy returns a Promise, not a Worker.

A more robust version — **prefetch the blob URL**, then load the viewer:

```html
<script>
(async () => {
  const stlBase = 'https://ipfs.konubinix.eu/p/bafybeickotxpnjv4qye2fbkk5e7q4edk563tpxjca7svcxgj2nbom4c7oa/';
  const workerUrl = stlBase + 'load_stl.min.js';
  const blob = await fetch(workerUrl).then(r => r.blob());
  const blobUrl = URL.createObjectURL(blob);

  const OriginalWorker = Worker;
  Worker = function(url, opts) {
    if (typeof url === 'string' && url.includes('load_stl')) {
      return new OriginalWorker(blobUrl, opts);
    }
    return new OriginalWorker(url, opts);
  };
  Worker.prototype = OriginalWorker.prototype;

  const s = document.createElement('script');
  s.src = stlBase + 'stl_viewer.min.js';
  document.head.appendChild(s);
})();
```

This:
1. Prefetches `load_stl.min.js` and creates a same-origin Blob URL
2. Monkey-patches the `Worker` constructor to redirect any `load_stl` worker to the Blob URL
3. Only then loads `stl_viewer.min.js`
